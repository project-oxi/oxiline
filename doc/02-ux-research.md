# 02. UX Research — 최근 루틴/타임블로킹 앱 리서치와 디자인 원칙

2026년 현재 시점 기준으로 조사한 내용을 바탕으로, OxiLine이 "트렌디하다"고 느껴지기 위해 차용할
패턴과, 의도적으로 피할 패턴을 정리한다.

## 2.1 Structured (unorderly GmbH) — 세로 타임라인의 표준을 만든 앱

- 캘린더와 투두를 하나의 **연속된 세로 타임라인**으로 합친 것이 핵심 정체성. "아침 루틴부터 저녁
  마무리까지" 하루 전체를 하나의 선으로 시각화한다.
- **Inbox(받은함)** 패턴: 아직 시간이 정해지지 않은 할일을 담아두는 별도 공간을 둬서 메인 타임라인이
  어수선해지지 않게 한다. → OxiLine의 "백로그" 개념과 정확히 대응.
- 레이아웃 밀도를 **Full / Simplified / Minimal** 세 단계로 사용자가 고를 수 있게 한다 — 미니멀을
  표방하는 앱도 정보 밀도 선택권을 준다는 점이 인상적.
- 2025년의 4.0 리뉴얼에서 주간/월간 뷰를 추가했지만, 여전히 "핵심은 하루 단위 세로 타임라인"이라는
  정체성을 유지했다.
- 최근에는 에너지/생체 리듬(에너지 모니터, 사이클 트래킹) 같은 "몸 상태 인지형" 기능까지 확장했는데,
  이는 OxiLine의 범위 밖(Non-goal)이지만 "하루 관리 앱은 결국 몸의 리듬을 반영해야 한다"는 방향성
  자체는 참고할 가치가 있다 (예: 루틴에 "아침/오후/저녁" 같은 느슨한 시간대 은유를 남겨두는 정도).

**차용할 것**: 세로 타임라인 + Inbox 분리, 레이아웃 밀도 선택.
**피할 것**: 기능 과적재(에너지 모니터, AI 자동 생성, 멀티플랫폼 위젯) — OxiLine은 Non-goal로 명시.

## 2.2 Sunsama — 미니멀리즘과 "워크로드 경고"의 정석

- 좌측 할일 리스트 + 우측 캘린더라는 2분할 레이아웃. 화려한 뷰(Gantt, Kanban)를 의도적으로 배제하고
  "하루/주 단위 계획"이라는 단일 기능에 집중한다. 리뷰에서 반복적으로 나오는 표현: *"다른 도구들은
  칸반, 간트, 타임라인, 서브태스크, 커스텀 필드… 결국 안 쓸 기능을 잔뜩 준다"* — Sunsama는 그렇게
  하지 않는다.
- **워크로드 경고(overcommit warning)**: 오늘 계획한 일의 예상 소요 시간 합이 가용 시간을 넘으면
  경고하고, 초과분을 뒤로 미루거나(defer) 백로그로 보내라고 권한다.
- 키보드 단축키가 매우 촘촘하다 (예: `D`로 미루기, `Z`로 백로그 이동, `Shift+F`로 채널 필터).
- 하루 시작(Daily Planning)과 하루 마감(Daily Shutdown)이라는 **의례(ritual)** 형태의 플로우를
  강제성 있게 제공한다.

**차용할 것**: 워크로드 총합 표시(오늘 계획된 시간 합계를 상단에 조용히 표시), 키보드 단축키를
아낌없이 제공, 기능을 더하기보다 빼는 태도.
**피할 것**: 강제성 있는 "일일 계획 의례" 플로우는 OxiLine에는 과함 — OxiLine은 언제든 열어서 바로
보고 바로 편집하는 가벼운 도구를 지향하므로, 워크로드 경고는 강제 모달이 아니라 조용한 인라인 표시로만
차용한다 (`07-ui-screens-and-flows.md` §7.2 참고).

## 2.3 Amie — 키보드 퍼스트, 절제된 비주얼 취향

- "아름다움에 값을 지불한다"는 평가를 받을 정도로 비주얼 완성도에 공을 들인 캘린더+투두 앱.
  파스텔톤의 절제된 팔레트, 빠른 자연어 캡처, 캘린더 우선 정체성.
- 키보드 우선 내비게이션이 핵심 가치 제안 중 하나 — 마우스 없이 일정을 만들고 옮길 수 있다.
- 반면 팀/전문가용 기능은 의도적으로 얕다 — "예쁘지만 깊이는 없다"는 것이 정직한 평가.

**차용할 것**: 빠른 캡처(Quick Add), 커맨드 팔레트형 키보드 내비게이션, "기능은 얕아도 완성도는
타협하지 않는다"는 태도.
**피할 것**: 파스텔 팔레트를 그대로 베끼지 않는다 — OxiLine은 Oxi 생태계 고유의 색 정체성이 필요하다
(`06-design-system.md`에서 별도로 다룸).

## 2.4 한국의 "갓생(God-saeng)" 루틴 앱 — 실행 마찰을 없애는 문화적 맥락

한국 생산성 앱 시장에서 2025~2026년 사이 두드러진 트렌드는 "갓생"이다. 이는 단순한 to-do 관리가 아니라
**"의지 없이도 실행되는 환경을 만들어주는 것"**을 핵심 가치로 삼는다. 조사한 대표 앱(루티너리 등)의
공통 패턴:

- **"다음 할일" 자동 안내**: 사용자가 "이제 뭘 해야 하지?"를 고민하지 않도록, 지금 실행해야 할 항목을
  앱이 먼저 알려준다 (푸시/음성 안내). → 이것이 정확히 OxiLine의 **플로팅 HUD**가 풀려는 문제다.
  "인지 부하를 줄인다"는 표현이 리뷰에 그대로 등장한다.
- **유연한 반복 규칙**: 매일이 아니라 "월/수/금만", "격주", "매월 n번째 n요일" 같은 세밀한 반복 규칙을
  지원한다. → `03-data-model.md`의 `weekday_mask` + `effective_from/until` 설계에 반영.
- **실행 중 유연성**: 루틴 실행 도중에도 일시정지, 시간 추가, 순서 변경, 건너뛰기가 가능해야 한다 —
  "완벽해야 한다는 압박감을 줄이기 위해서"라는 설명이 인상적이다. → OxiLine의 "오늘만 건너뛰기(skip)"
  / "오늘만 시간 수정" 개념(occurrence override)과 직접 연결된다.
- **무광고·클린 앱**을 강하게 선호하는 정서 — 미니멀 요구사항과 일치.

**차용할 것**: "다음 할일" 즉시 안내라는 핵심 문제의식(HUD의 존재 이유), 유연한 반복 규칙, 실행 중
수정의 관대함.
**피할 것**: 스트릭/포인트/리포트 점수화 — Non-goal로 명시(§1.6). OxiLine은 동기부여 게이미피케이션
대신 "마찰 없는 확인"에 집중한다.

## 2.5 macOS 유틸리티 트렌드 — Raycast/CleanShot류의 "살아있는 메뉴바"

Structured/Sunsama/Amie는 모두 모바일-퍼스트 앱이라 macOS 유틸리티 고유의 트렌드도 별도로 반영해야
한다. 2025~2026년 macOS 생산성 유틸리티(Raycast, CleanShot X, Bartender류)의 공통 언어:

- 메뉴바 아이콘 자체가 정보를 담는다 (진행률, 카운트다운 등을 아이콘에 그려 넣음).
- 전역 단축키로 뜨는 **비활성화(non-activating) 플로팅 패널** — 클릭해도 현재 포그라운드 앱의 포커스를
  뺏지 않는, Spotlight류의 가벼운 오버레이.
- Dock에 아이콘을 노출하지 않는 "accessory" 형태의 상주 프로세스.

이 세 가지는 전부 `04-architecture.md`에서 구체적인 Tauri 구현 방식(tauri-nspanel, ActivationPolicy,
tray-icon)으로 이어진다.

## 2.6 종합: OxiLine이 채택하는 디자인 원칙 7가지

1. **시간은 배경이 아니라 주인공이다.** 다른 앱들은 시간을 좌표계로 쓰지만, OxiLine은 시간의 흐름
   자체를 눈에 보이는 애니메이션으로 만든다 (Now Line이 실시간으로 미끄러지듯 이동).
2. **캘린더처럼 보이되, 캘린더처럼 계획하지 않는다.** 세로 타임라인(Structured 패턴)은 채택하되,
   "약속을 잡는" 무거운 플로우는 만들지 않는다.
3. **뺄셈의 미학.** Sunsama의 태도를 따라, 기능을 하나 추가할 때마다 "이게 정말 하루 관리에 필요한가"를
   묻는다. 서브태스크 트리, 프로젝트, 칸반은 만들지 않는다.
4. **인지 부하 제로가 목표.** 갓생 앱들의 핵심 통찰 — "지금 뭘 해야 하지?"라는 질문에 0.5초 안에
   답한다. 이것이 플로팅 HUD의 존재 이유이자 존재 근거다.
5. **실행 중 유연성.** 루틴은 신성불가침한 계획표가 아니다. 오늘 하루만 건너뛰거나 시간을 옮기는 것이
   항상 마찰 없이 가능해야 한다 (occurrence override).
6. **키보드가 먼저, 마우스는 다음.** Amie/Sunsama 모두 키보드 우선을 핵심 가치로 삼는다. 커맨드
   팔레트(⌘K), 빠른 추가, 완료 체크 전부 키보드로 가능해야 한다.
7. **에이전트도 사용자다.** 이 원칙은 다른 어떤 리서치 대상 앱에도 없는, Oxi 생태계 고유의 원칙이다.
   화면이 없는 클라이언트(CLI/에이전트)가 사람과 동등하게 데이터를 다룰 수 있어야 하고, 이는 UI를
   나중에 붙인 게 아니라 애초에 코어 아키텍처 설계 단계부터 들어가야 한다 (`04-architecture.md`).
