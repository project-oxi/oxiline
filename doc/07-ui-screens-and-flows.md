# 07. UI Screens & Flows — 화면별 상세 설계

## 7.0 창(Window) 목록 개요

| 창 label | 종류 | 설명 |
|---|---|---|
| `main` | 표준 창 | Day/Week/Backlog 뷰를 담는 메인 창. 리사이즈 가능, 최소 360×480 |
| `hud` | tauri-nspanel 플로팅 패널 | 전역 단축키로 등장, 2초 후 자동 소멸 |
| `onboarding` | 표준 창 (최초 1회) | 최초 실행 시에만 표시, 이후 재사용 안 함 |

메인 창은 macOS 오버레이 타이틀바(`titleBarStyle: Overlay`)를 사용해, 네이티브 트래픽 라이트는
유지하되 타이틀바 영역에 커스텀 헤더(오늘 날짜, 산화 바 등)를 겹쳐 그린다 — Arc/Linear 계열 최신
Mac 앱들의 공통 관용구.

### 구성 요소

- **날짜 내비게이터**: 헤더 중앙의 날짜 텍스트 좌우에 얇은 화살표(`←`/`→`)가 호버 시에만 나타나고,
  클릭 시 하루씩 이동. 날짜 텍스트 클릭 시 미니 날짜 피커 팝오버. `T` 키로 오늘로 즉시 복귀.
- **시간 눈금(hour rail)**: 좌측 고정 폭 56px, `--type-time-md` 모노스페이스로 정시만 표시(예:
  `06:00`). `settings.day_start_hour`~`day_end_hour` 범위만 렌더링하되, 스크롤로 그 밖도 접근 가능.
- **블록(Block)**: 절대 위치 지정(`top = start_minute 비례, height = duration_minute 비례`). 겹치는
  경우 Google Calendar와 동일한 방식으로 폭을 n등분해 나란히 배치. 블록 내부 표기 우선순위(공간 부족
  시 아래부터 생략): ① 제목 ② 시간 범위 ③ 남은/전체 소요시간 배지. 좌측에 카테고리 색 4px 보더.
- **가상 vs 구체화 구분**: 가상 occurrence는 살짝 더 낮은 불투명도(92%)와 점선 좌측 보더로 "아직
  건드리지 않은 루틴"임을 은근히 표시한다 — 사용자가 상호작용하는 순간(체크, 드래그, 우클릭) 즉시
  구체화되어 실선/완전 불투명으로 전환된다. 이 전환에 별도 애니메이션은 넣지 않는다(과한 연출 방지).
- **빈 슬롯 클릭**: 타임라인의 빈 시간대를 클릭하면 그 시각을 시작 시각으로 미리 채운 빠른 추가
  인풋이 그 자리에 인라인으로 나타난다(모달 없이 — Amie의 "즉각적인 캡처" 철학 반영).
- **워크로드 표시줄**: 하단 얇은 바. `workload_warning_minutes` 설정값을 넘기면
  `--signal-rust`로 톤만 살짝 바뀐다("여유 있음" → "빠듯해요"). 클릭 가능한 모달이나 강제 플로우는
  없음 — Sunsama처럼 강제하지 않고 정보만 조용히 제공한다(`02-ux-research.md` §2.2 참고).

## 7.2 백로그(Inbox) 뷰

날짜 없는 `tasks`(`date IS NULL`)의 단순 리스트. 드래그하여 메인 타임라인의 특정 시간대로 놓으면
`date`+`start_minute`이 채워지며 즉시 스케줄된 항목으로 전환된다(드래그 앤 드롭은 Phase 2로 미뤄도
되나, 최소한 "이 항목을 오늘 O시로 예약" 같은 컨텍스트 메뉴 액션은 MVP에 포함한다).

```
┌───────────────────────────────────┐
│  백로그 (3)                        │
├───────────────────────────────────┤
│ ○ 장보기                     ⋮     │
│ ○ 책 반납하기                 ⋮     │
│ ○ 치과 예약 전화               ⋮     │
└───────────────────────────────────┘
```

빈 상태 문구: "아직 정해지지 않은 할일이 없어요. ⌘K로 빠르게 추가해보세요." — 빈 화면도 행동을
유도하는 안내로 취급한다(frontend-design 원칙).

## 7.3 주간(Week) 뷰 — Phase 2

7개의 축소된 세로 미니 타임라인을 가로로 나란히 배치, 각 열 상단에 요일 + 날짜. 루틴이 어느 요일에
어떻게 분포되어 있는지 한눈에 파악하는 용도(Structured 4.0의 주간 뷰 참고, `02-ux-research.md` §2.1).
MVP에는 포함하지 않으며 탭은 미리 존재하되 "곧 제공됩니다" placeholder로 둔다.

## 7.4 루틴 관리 (Routine Manager)

설정 진입점 또는 헤더의 "루틴 관리" 버튼으로 여는 전용 패널(모달 아님 — 전체 목록을 다루므로 사이드
시트 형태 권장, 폭 480px).

```
┌───────────────────────────────────────┐
│  루틴 관리                        + 추가 │
├───────────────────────────────────────┤
│ ●  아침 운동        07:00 · 30분        │
│    월 화 수 목 금                ⋯  ⏸  │
├───────────────────────────────────────┤
│ ●  출근 준비        07:30 · 30분        │
│    월 화 수 목 금                ⋯  ⏸  │
├───────────────────────────────────────┤
│ ○  주말 브런치      10:00 · 60분  (일시정지)│
│    토 일                          ⋯  ▶  │
└───────────────────────────────────────┘
```

각 행: 색 도트(카테고리) · 제목 · 시각 · 소요시간, 두 번째 줄에 요일 배지(선택된 요일만 강조),
우측에 `⋯`(수정/삭제) 및 일시정지/재개 토글. 요일 반복 선택 UI는 월~일 7개 토글 버튼 + "평일만"/
"주말만"/"매일" 프리셋 칩 3개.

## 7.5 빠른 추가 / 커맨드 팔레트 (⌘K)

Amie/Sunsama/Linear류의 표준 패턴. 입력창 하나 + 아래 결과 리스트. MVP 범위:

- 텍스트 입력만으로 새 백로그 항목 생성(`Enter`).
- `@시간` 힌트 문법 지원 (예: `장보기 @18:00` → 오늘 18시로, `@내일 15:00` → 내일 15시로). 이는 완전한
  자연어 파싱이 아니라, 한정된 토큰(`@HH:MM`, `@오늘`, `@내일`, `@모레`)만 인식하는 **가벼운 로컬
  파서**이며, `05-cli-spec.md` §5.1에서 CLI는 이런 파싱을 하지 않기로 한 것과 모순되지 않는다 —
  이건 GUI 편의 기능이고, 실제로는 파싱 후 구조화된 `add_task(title, date, start_minute, ...)` 커맨드
  하나만 호출하기 때문이다.
- 기존 항목 검색(제목 부분 일치) 후 Enter로 완료 체크.
- 화살표로 탐색, `Esc`로 닫기.

## 7.6 플로팅 HUD (2초 오버레이)

가로 폭 360px, 높이 약 140px의 둥근(16px) 카드. 배경은 `--surface-raised`에 살짝의 블러/비네트
(macOS 네이티브 vibrancy, `window-vibrancy` 크레이트 활용 가능)를 얹어 "이건 지금 떠 있는 것"임을
그림자와 함께 전달한다.

```
┌─────────────────────────────────────┐
│  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓●──────────────────   │ ← 축소된 산화 바
│                                       │
│   지금 · 집중 작업 블록               │
│   10:28                     32분 남음 │  ← 시간은 JetBrains Mono
│                                       │
│   다음 · 팀 스탠드업 (11:00, 32분 후) │
└─────────────────────────────────────┘
```

- 진행 중인 항목이 없으면: `지금 · 자유 시간` + 다음 항목까지 남은 시간만 크게 표시.
- 오늘 남은 일정이 아예 없으면: `오늘 예정된 일이 모두 끝났어요` 한 줄만 표시(빈 화면도 안내로 취급).
- 클릭 시 메인 창을 열고 해당 시각으로 스크롤(포커스를 가져가는 유일한 상호작용 — 그 전까지는
  `no_activate` 상태 유지, `04-architecture.md` §4.4).
- 하단에 아주 작은 글씨로 단축키 힌트(`Esc로 닫기`)는 넣지 않는다 — 2초짜리 UI에 읽을 게 많으면
  안 되므로 정보량을 의도적으로 최소화한다.

## 7.7 메뉴바 트레이 메뉴

좌클릭: 메인 창 토글(숨김↔표시). 우클릭 또는 좌클릭 시 드롭다운(구현 편의상 좌클릭 하나로 통일 권장):

```
지금: 집중 작업 블록 (32분 남음)      ← 클릭 불가, 정보 행
────────────────────────────
OxiLine 열기                    ⌘⇧O 아님, 별도 표기 없음
빠른 추가...                    ⌘K
────────────────────────────
환경설정...                     ⌘,
로그인 시 자동 실행           ✓
────────────────────────────
OxiLine 종료
```

## 7.8 설정(Preferences)

메인 창 내 슬라이드 오버 패널(별도 창 아님, 구현 단순화). 섹션:

1. **일반**: 언어(한국어/English/시스템), 테마(라이트/다크/시스템), 로그인 시 자동 실행 토글.
2. **타임라인**: 하루 시작/종료 시각, 주 시작 요일, 워크로드 경고 임계값.
3. **단축키**: 전역 단축키 레코더 UI(클릭 후 원하는 키 조합 입력 → 캡처), HUD 표시 시간 슬라이더
   (1~5초).
4. **카테고리**: 목록 + 색상(hue 슬라이더, OKLCH L/C는 고정) + 추가/삭제.
5. **데이터**: DB 파일 경로 표시(Finder에서 보기 버튼), 내보내기(JSON 저장 — CLI `export`의 GUI
   래퍼), `oxiline` CLI 설치 안내(터미널에서 `oxiline --help`로 확인하라는 짧은 문구 + 코드 블록).
6. **정보**: 버전, "닫아도 메뉴바에서 계속 실행됩니다" 안내 문구 재노출(온보딩에서 놓쳤을 사용자를
   위해).

## 7.9 온보딩 (최초 1회)

3단계, 각 단계 다음/건너뛰기:

1. **환영**: 한 줄 정체성 소개("하루는 흐릅니다. OxiLine은 그 흐름을 보여줍니다") + 언어 선택.
2. **백그라운드 동작 설명**: "창을 닫아도 OxiLine은 메뉴바에 남아 언제든 단축키로 지금 할일을 보여줘요"
   — 이 문장 하나가 `04-architecture.md` §4.3에서 다룬 상주 프로세스 모델을 사용자에게 정확히
   전달하는 유일한 접점이므로 문구를 가볍게 넘기지 않는다.
3. **단축키 설정**: 기본값(`⌘⇧O`) 확인 또는 즉시 변경 + 손쉬운 사용 권한이 필요할 수 있다는 안내
   (권한 프롬프트가 뜨면 허용 유도, 거부해도 앱은 계속 쓸 수 있음을 명시).

## 7.10 키보드 단축키 전체 표

| 단축키 | 동작 | 범위 |
|---|---|---|
| `⌘⇧O` (기본값, 변경 가능) | 플로팅 HUD 표시 | 전역(앱 밖에서도) |
| `⌘K` | 커맨드 팔레트 / 빠른 추가 | 앱 내 전역 |
| `⌘N` | 새 할일(현재 보고 있는 날짜에) | 메인 창 |
| `⌘,` | 환경설정 열기 | 메인 창 |
| `T` | 오늘로 이동 | Day/Week 뷰 |
| `←` / `→` | 이전/다음 날 | Day 뷰 |
| `1` / `2` / `3` | 오늘/주간/백로그 탭 전환 | 메인 창 |
| `Enter` (항목 포커스 시) | 완료 토글 | 리스트/타임라인 |
| `⌫` (항목 포커스 시) | 삭제(루틴이면 "오늘만 건너뛰기" 확인 없이 즉시) | 리스트/타임라인 |
| `Esc` | 팔레트/패널/HUD 닫기 | 전역 |

## 7.11 빈 상태·에러 카피 원칙 (frontend-design 원칙 적용)

- 빈 상태는 항상 "왜 비어있는지 + 다음에 뭘 할 수 있는지"를 함께 말한다. 예: 백로그가 비었을 때
  "아직 정해지지 않은 할일이 없어요. ⌘K로 빠르게 추가해보세요."
- 에러는 사과하지 않고 사실과 다음 행동만 말한다. 예: 단축키 등록 실패 시 "이 단축키는 다른 앱이
  이미 사용 중이에요. 다른 조합을 입력해주세요." (원인 회피/사과 없음, 무엇을 하면 되는지 명확히)
- 버튼 라벨은 결과와 동일한 동사를 쓴다: "루틴 추가" 버튼 → 완료 토스트 "루틴을 추가했어요"(제출/저장
  같은 애매한 동사 지양).
