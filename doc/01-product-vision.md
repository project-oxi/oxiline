# 01. Product Vision — OxiLine이 무엇이고, 무엇이 아닌가

## 1.1 한 문장 정의

OxiLine은 **"일정(schedule)"이 아니라 "하루의 흐름(routine of a day)"을 관리**하는 macOS 네이티브 유틸리티다.
캘린더 앱처럼 미래의 약속을 잡는 도구가 아니라, 지금 이 순간 내가 무엇을 해야 하는지, 오늘 하루가
어떻게 설계되어 있는지를 살아있는 타임라인으로 보여주는 도구다.

핵심 은유는 **"재생 헤드(playhead)"**다. 현재 시각은 정지해 있지 않고, 미디어 플레이어의 재생 바처럼
끊임없이 흐른다. 할 일들은 그 흐름 위에 배치된 구간(block)이고, 사용자는 그 흐름을 "따라간다."

## 1.2 왜 기존 캘린더/투두 앱과 다른가

| 관점 | 전통적 캘린더 | 전통적 투두 리스트 | OxiLine |
|---|---|---|---|
| 시간의 성격 | 정적인 좌표 (이 약속은 3시다) | 시간 없음 (마감일만) | **흐르는 것** — 지금이 어디인지가 항상 화면에 존재 |
| 반복의 단위 | 이벤트 반복 규칙 | 반복 없음이 기본 | **하루의 구조 자체가 반복** (아침 루틴, 출근 루틴) |
| 주 사용 순간 | 계획할 때 (주간 리뷰) | 체크할 때 | **지금 뭘 해야 하지?** 를 하루 종일 여러 번 묻는 순간 |
| 접근 방식 | 앱을 열어서 본다 | 앱을 열어서 본다 | **앱을 열지 않고도** 단축키로 2초 확인 |

즉 OxiLine의 경쟁자는 Google Calendar가 아니라 "지금 뭐 해야 하지?"라는 질문에 답하지 못해서
생기는 결정 피로(decision fatigue)다. 이는 `02-ux-research.md`에서 다루는 Structured, Sunsama와
한국의 "갓생 루틴" 앱들이 공통적으로 풀려고 하는 문제이기도 하다.

## 1.3 Oxi 생태계 안에서의 위치

사용자가 이미 구축한 Rust 기반 "Oxi" 생태계:

- **oxi** — 터미널 AI 에이전트
- **oxiBrowser** — 순수 Rust 헤드리스 브라우저
- **oxiOS** — oxi-sdk 기반 에이전트 OS
- **oxiNot** — 미니멀 마크다운 노트 앱
- **oxiPage** — 블로그 빌더
- **OxiLine** *(신규)* — 하루/루틴 관리 앱

이 생태계의 공통 원칙은 다음과 같고, OxiLine도 예외 없이 따른다.

1. **Rust 우선주의**: 모든 핵심 로직은 Rust로 작성한다. UI 레이어(React)는 얇은 표현 계층일 뿐,
   비즈니스 로직·데이터 검증·영속성은 전부 Rust 코어 크레이트에 있다.
2. **CLI가 1급 시민이다**: GUI가 CLI의 래퍼가 아니라, 오히려 **CLI와 GUI가 동일한 코어 라이브러리를
   공유하는 두 개의 얇은 클라이언트**다. 이는 사용자가 에이전트(AI)에게 이 앱들을 "도구"로 쥐어주는
   워크플로우의 핵심 전제다 — 에이전트는 GUI를 열 수 없지만 CLI는 호출할 수 있다.
3. **로컬 퍼스트**: 클라우드 동기화, 계정, 서버는 v1 범위에 없다. 모든 데이터는 로컬 SQLite 파일 하나에 있다.
4. **미니멀리즘**: 기능을 최대한 쌓지 않는다. Structured나 Sunsama가 가진 기능의 70%를 의도적으로 버리고,
   "지금 흐름을 본다"는 한 가지에 집중한다.

## 1.4 타깃 사용자

- 1차 사용자: 개발자 본인. 터미널/에이전트 워크플로우에 이미 익숙하고, 자신의 하루도 코드처럼
  선언적으로 관리하고 싶어하는 사람.
- 2차 사용자(확장 시): "갓생(God-saeng, 자기계발형 하루 관리)" 트렌드에 익숙한 사용자 — 아침 루틴,
  운동, 집중 시간 등을 요일별로 반복 설정하고, 지금 뭘 해야 할지 자동으로 안내받고 싶어하는 사람들.
  (자세한 리서치는 `02-ux-research.md` §2.4 참고)

## 1.5 핵심 기능 5줄 요약

1. **오늘 타임라인**: 세로 시간축 위에 루틴/할일이 구간(block)으로 배치된 하루 뷰. 실시간으로 흐르는
   "지금 선(Now Line)"이 화면을 가로지른다.
2. **루틴**: 요일 반복 규칙을 가진 시간 구간 템플릿. 매일 다시 만들 필요 없이 하루의 뼈대를 구성한다.
3. **날짜별 할일 / 백로그**: 특정 날짜에 고정된 일회성 항목과, 날짜가 없는 미정 할일(Inbox)을 모두 지원.
4. **전역 단축키 플로팅 HUD**: 어떤 앱을 쓰고 있든 단축키 한 번으로 "지금 뭘 해야 하지"에 대한 답이
   2초간 화면 위에 떠 있다가 사라진다.
5. **CLI + 에이전트 연동**: `oxiline` CLI로 사람도, AI 에이전트도 동일한 데이터를 읽고 쓸 수 있다.

## 1.6 Non-goals (v1에서 의도적으로 하지 않는 것)

- ❌ 팀 협업, 공유, 멀티유저 — 철저히 개인용 로컬 앱.
- ❌ 클라우드 동기화 / 계정 로그인 — 로컬 SQLite 파일이 유일한 진실의 원천(source of truth).
- ❌ Windows/Linux 지원 — macOS 단일 타겟. 크로스플랫폼을 위한 추상화 비용을 지불하지 않는다.
- ❌ 복잡한 프로젝트 관리(서브태스크 트리, 칸반, 간트 프로젝트뷰) — Sunsama가 이미 지적하듯,
  "쓰지도 않을 기능"은 만들지 않는다.
- ❌ 습관 스트릭/게이미피케이션 점수 시스템 — 갓생 앱들의 리서치에서 확인했지만, OxiLine은 동기부여형
  앱이 아니라 실행 보조 도구를 지향한다. (완전 배제는 아니고 Phase 3 이후 검토, `08-roadmap.md` 참고)
- ❌ AI 자동 일정 생성(Structured AI 같은 자연어 → 일정 자동 배치) — v1 범위 밖. 대신 CLI를 통해
  사용자의 개인 에이전트가 이 역할을 대신하게 하는 것이 OxiLine의 철학과 더 맞다. 즉 "AI 기능을 내장"하는
  대신 "AI가 쓸 수 있는 도구"가 되는 쪽을 택한다.

## 1.7 용어 정의 (Glossary)

구현 시 코드 식별자는 영어를 쓰되, 문서/UI 카피에서 아래 용어를 일관되게 사용한다.

| 한글 용어 | 영어 코드 식별자 | 의미 |
|---|---|---|
| 루틴 | `routine` / `routine_block` | 요일 반복 규칙을 가진 시간 구간 템플릿 |
| 할일 | `task` | 특정 날짜(또는 날짜 없음)에 속한 항목. 루틴에서 파생되었거나 수동 생성됨 |
| 발생(occurrence) | `occurrence` | 특정 날짜에 루틴이 실제로 나타나는 가상 인스턴스 (아직 DB에 저장 안 됐을 수도 있음) |
| 구체화 | `materialize` | 가상 occurrence를 실제 `task` 행으로 저장하는 과정 (완료 체크, 시간 수정, 오늘만 건너뛰기 등) |
| 백로그 / 받은함 | `inbox` / `backlog task` | 날짜가 지정되지 않은 할일 |
| 지금 선 | `now line` (내부 코드명: Oxide Line) | 실시간으로 흐르는 현재 시각 표시선 |
| 산화 바 | `oxide bar` | 하루 전체를 가로로 압축한 미니 진행 바 (시그니처 비주얼, `06-design-system.md` 참고) |
| 플로팅 HUD | `hud panel` | 전역 단축키로 뜨는 2초짜리 오버레이 패널 |
