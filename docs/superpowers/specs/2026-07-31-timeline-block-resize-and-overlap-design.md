# 타임라인 블록 리사이즈 + 드래그 생성 + 겹침 — 설계

- **날짜:** 2026-07-31
- **관련 문서:** `doc/03-data-model.md` §3.5/§3.7, `doc/07-ui-screens-and-flows.md` §7.1
- **영향 코드:** `crates/oxiline-app/src/components/DayTimeline.tsx`, `BlockView.tsx`, `lib/dnd.tsx`

## 배경 및 목표

현재 타임라인의 스케줄 카드는 **항상 30분 고정 길이**로만 생성되며, 한 시간대에 카드를 하나만
등록할 수 있는 것처럼 보인다. 실제로는 "코딩 세션이 도는 동안 기사를 읽고 블로그를 쓴다"처럼
하나의 시간대에 여러 활동이 병렬로 존재하며, 활동의 길이도 30분이 아닌 여러 시간일 수 있다.

목표:
1. 카드를 드래그해 길이를 자유롭게 늘린다(여러 시간).
2. 한 시간대에 여러 카드를 의도적으로 겹쳐 배치할 수 있다(동시 병렬 활동 표현).
3. 빈 시간대를 드래그해 원하는 길이의 블록을 한 번에 만든다.

## 현재 상태 (검증된 사실)

- **길이는 제한이 없었다.** `tasks.duration_minute`는 `Option<u16>`(1–1440)이고 `TimelineItem.duration_minute`도 동일(`model.rs:77,112`). "30분만" 동작은 단일 하드코딩 값에서 온다: 빠른 추가 컴포저의 `durationMinute: 30`(`DayTimeline.tsx:268`)와 백로그→타임라인 드롭의 `durationMinute: 30`(`dnd.tsx:43`).
- **겹침은 이미 렌더링된다.** `layout()`(`DayTimeline.tsx:21–57`)이 Google-Calendar식 탐욕 레인 배정으로 겹치는 항목을 N개 열로 분할. `BlockView`는 이미 `left`/`columns` prop을 받아 열 렌더링.
- **명령도 준비됨.** `create_task`/`update_task`가 이미 `start_minute` + `duration_minute`를 받음(`commands.rs:226,251`).
- **부재:** (a) `BlockView`엔 이동 드래그(`useDraggable`)만 있고 길이 변경 그립이 없음. (b) 생성 흐름에 30분 외의 길이 지정이 없음. (c) 겹침이 의도적 액션으로 노출되지 않음(빈 시간대를 클릭해야만 생성, 겹치게 만들 길이 조작 없음).

> 즉 이 설계는 **상호작용 레이어**에 국한된다. 아키텍처·데이터 모델 재설계가 아니다.

## 설계 결정 요약

| 항목 | 결정 |
|---|---|
| 겹침 한도 | 완화된 상한 3개. 4개째부터 "+N 더 보기" 칩으로 접기 |
| 리사이즈 가장자리 | 카드 **아래쪽**만. 본문 드래그는 이동 유지 |
| 만들기 흐름 | 빈 시간대 **드래그**로 길이만큼 블록 생성(클릭은 기존 인라인 입력 유지) |
| 상호작용 아키텍처 | 이동=기존 dnd-kit 유지, 리사이즈·드래그생성=격리된 pointer-event 핸들러 |
| 스냅 | 이동 5분, 리사이즈·생성 15분 |
| 백엔드/스키마 | **변경 없음** (프론트엔드 전용) |

## 1. 상호작용 아키텍처

현재 `BlockView` 전체가 dnd-kit `useDraggable`의 "이동" 드래그를 잡는다. 리사이즈와 드래그-생성을
얹는 세 안:

- **A (채택): 제스처를 잡는 위치로 분리.** 이동은 dnd-kit 그대로. 리사이즈 핸들과 드래그-생성은
  **독립된 pointer-event 핸들러**로 추가하고 `onPointerDown`에서 `stopPropagation`해 이동 드래그
  발화를 막는다. 세 제스처가 "어디를 잡았느냐"로 분리되고 기존 DnD를 건드리지 않는다.
- **B (기각):** dnd-kit 커스텀 센서로 전부 통합. dnd-kit은 translate 이동에 맞춰져 리사이즈 델타는
  결국 직접 짜야 해 코드가 줄지 않음.
- **C (기각):** 이동까지 pointer-events로 재작성. 작동 중인 DnD 리스크.

**A로 간다.** 격리성·최소 침습성 때문.

## 2. 리사이즈 핸들 (아래쪽 가장자리)

- 카드 하단에 **전폭 8px 그립 스트립**, `cursor: ns-resize`. 항상 아주 옅은 그래버 자국(¨¨¨)이
  보이고 호버 시 진해진다 — 숨기면 발견 불가(사용자 원 불만의 핵심).
- `pointerdown`: 포인터 캡처 + 이동 드래그 중단(`stopPropagation`). px 델타 → 분 단위 변환.
- **실시간 미리보기**: 로컬 state로 높이를 즉시 갱신(DB 아님). `pointerup` 시
  `update_task({ duration_minute })` 1회 커밋 + 타임라인 쿼리 무효화.
- **바닥 15분, 상한 = 당일 종료 시각(`day_end_hour`)에서 클램프.**
- 가상 루틴 occurrence 리사이즈 시 먼저 `materialize_if_virtual`로 구체화 후 갱신 — §3.7
  "그날의 스냅샷" 원칙 준수(오늘만 길이 변경, 루틴 원본은 미동).
- **키보드 동등성(접근성):** 포커스된 카드에서 `Shift+↑/↓`로 15분 단위 증감(기존 `Enter`=완료
  토글, `Backspace/Delete`=건너뛰기/삭제 단축키와 충돌 없음).

## 3. 드래그로 만들면서 길이 지정

빈 타임라인 영역(`DropZone`, `DayTimeline.tsx:322`)에서의 제스처:

1. `pointerdown`: 시작 분 기록.
2. **~8px 이동 임계치** 초과 시 "생성 중" 모드 진입: 반투명 **고무줄 블록** + 실시간 범위 라벨
   (`09:00 – 10:30 · 90분`). 15분 스냅.
3. `pointerup`: 고무줄 영역이 **인라인 컴포저**로 전환 — 길이는 배지로 고정 표시(`09:00 – 10:30 · 90분`),
   제목 입력 필드 포커스. 태스크는 아직 생성 **안 됨**: 기존 빠른추가(`DayTimeline.tsx:262`)와 동일한
   *커밋-온-엔터* 계약. `Enter`=`create_task({ start_minute, duration_minute, title })` 생성,
   `Esc`/포커스 아웃=취소(태스크 없음, 고무줄 소거). 이렇게 하면 빈 제목 태스크가 생기지 않고
   클릭-추가와 일관(클릭=30분 배지 컴포저, 드래그=드래그한 길이 배지 컴포저 — 둘 다 컴포저를 연다).
4. 임계치 미만(순수 클릭): 기존 §7.1 인라인 빠른추가 흐름 유지.

> ⚠ 주의: 이 분기는 dnd-kit `PointerSensor`의 거리 임계치가 **아니다**. `PointerSensor`는
> *draggable 활성화*만을 제어하며, `DropZone`의 `onClick`(`DayTimeline.tsx:361`)은 그 임계치
> 밖의 평범한 클릭 핸들러다. 따라서 합성 클릭 억제가 별도로 필요하다(§5).

## 4. 겹침 레이아웃 (완화된 상한 3)

- `layout()`은 **수정 없이** 진짜 깊이(true column count)만 계산 — 순수 레이아웃 함수를 그대로 둔다.
  이제 겹침이 *의도적*(드래그 생성/리사이즈로 빈 또는 찬 슬롯에 밀어 넣기)이므로 나란히 선 열이
  "동시 진행 중"을 자연스럽게 전달.
- **3열 클램프 + 오버플로우 집계는 `DayTimeline` 렌더 레이어**가 담당(`layout()`이 아님). 클러스터
  깊이가 4 이상이면 3개까지 나란히 렌더 + 나머지는 얇은 **"+N 더 보기" 칩**(4번째 열 위치). 클릭 →
  **읽기 전용 팝오버**로 숨겨진 항목 나열(제목 + 범위). v1은 "뭐가 숨겨졌는지" 보여주기만 하고 항목
  클릭=팝오버 닫기(보이는 3개로의 프로모션/스왑은 non-goal, §범위 외). 4개 이상은 드문 폴백이라
  팝오버가 레이아웃 리플로우를 최소화.
- **숨김 선택 규칙(결정적):** 클러스터를 `start_minute` 오름차순(동점 시 `duration_minute`
  내림차순, 그 다음 `id`)으로 정렬해 **앞 3개를 가시 열**, 나머지를 "+N 더 보기" 오버플로우로.
  팝오버도 같은 순서로 나열. (현재 진행 중 — now 선 관통 — 항목 강제 가시화는 v2 후보.)
- 완료/과거 항목과의 겹침 허용(스타일은 기존 뮤트 유지).

## 5. 합성 클릭 억제 불변식 (didDrag) — 중요

**문제:** 드래그-생성은 `DropZone` 노드 위의 원시 포인터 로직이지 dnd-kit 센서가 아니다. 브라우저는
`pointerdown → 이동 > 8px → pointerup` 이후에도 **합성 `click` 이벤트**를 발생시킨다. 이 click이
`DropZone`의 `onClick`(`DayTimeline.tsx:361–364`)에 닿으면, 방금 만든 블록 위에 빠른추가 컴포저가
뜬다 — **모든 드래그-생성이 이중 발화**된다.

**해결 (스펙 불변식):**
- `DropZone`에 `didDrag` ref(초기 `false`).
- pointermove가 임계치를 넘어 "생성 중" 모드에 진입한 최초 순간 `didDrag = true`.
- `onClick` 핸들러 진입 시 `if (didDrag.current) { didDrag.current = false; return; }` 로 단락.
- 정상 클릭(드래그 아님)은 `didDrag`가 `false`이므로 기존 `onAdd` 경로 유지.
- 안전장치: `pointerup`에서도 타임아웃(예: 0ms 또는 다음 틱) 후 `didDrag` 리셋을 고려할 수 있으나,
  click은 pointerup 직후 동기적으로 발화하므로 click 핸들러 내 리셋이 충분.

**검증:** `window.__mockLog`(audit mock)에 create_task 호출을 push하고, `page.mouse`로 드래그 후
create 호출이 **정확히 1회** 기록되는지 확인(tauri-v2-browser-audit-mock 스킬).

## 6. 불변식 및 엣지케이스

- 리사이즈·드래그-생성 모두 **15분 바닥, 당일 종료 시각 상한**으로 클램프.
- 드래그-생성이 종료 시각을 넘어가면 종료 시각에서 클램프(잘림).
- 가상 occurrence 조작 시 항상 `materialize_if_virtual` 선행(리사이즈·드래그-생성 모두).
- 하단 워크로드 표시줄은 `duration_minute` 합산(`DayTimeline.tsx:101`) → 쿼리 무효화로 자동 갱신,
  추가 코드 불필요.
- 리사이즈/드래그 중 `NowLine`, 산화 바(OxideBar) 등 절대위치 요소는 영향 없음(블록 높이만 변).

## 7. 스냅 단위

- 이동 = 5분(`SNAP_MINUTES`, `dnd.tsx:11` 유지).
- 리사이즈·생성 = 15분(`SLOT`, `DayTimeline.tsx:64` 및 정시 그리드 정렬).
- 미세한 비일관이나 타당: 이동은 이웃 근처 정밀도, 생성/리사이즈는 블록 형태가 목적. 필요 시 15분으로
  통일 가능(튜닝 포인트).

## 8. 백엔드/스키마 영향

- **없음.** `create_task`/`update_task`가 이미 `start_minute`/`duration_minute`을 받는다. 마이그레이션·
  Rust 도메인 타입 변경 없음. 전부 프론트엔드(`DayTimeline.tsx`, `BlockView.tsx`, `dnd.tsx`,
  `hooks.ts` 낙관적 갱신)에 머무른다.

## 9. 컴포넌트/파일 영향도

| 파일 | 변경 |
|---|---|
| `BlockView.tsx` | 하단 리사이즈 그립 추가(pointer 핸들러 + `stopPropagation`); `Shift+↑/↓` 키보드 증감 |
| `DayTimeline.tsx` | `DropZone`에 드래그-생성 pointer 로직 + `didDrag` 합성 클릭 억제; 고무줄 미리보기 오버레이; **렌더 레이어**에서 3열 클램프 + "+N 더 보기" 칩/팝오버(`layout()`은 true 깊이만 계산하도록 순수 유지) |
| `dnd.tsx` | 백로그→드롭 기본 30분은 유지하되, 필요 시 소스 색/기본길이 정책 일원화(선택) |
| `hooks.ts` | `useUpdateTask`/`useCreateTask` 재사용(새 훅 불필요); 낙관적 갱신은 기존 패턴 준수 |

## 10. 접근성

- 리사이즈는 마우스 pointer 외에 `Shift+↑/↓` 키보드 대안 제공(포커스된 카드).
- 고무줄 라벨·"+N 더 보기" 칩은 `aria-live` 영역으로 범위 변화를 스크린리더에 알림(간결하게).
- 그립은 키보드 포커스 가능한 영역(카드 자체가 포커스 단위이므로 카드 포커스 = 리사이즈 가능 상태).

## 11. 테스트 계획

- **리사이즈:** 카드 하단 그립을 60px(=60분) 드래그 → `update_task`가 새 `duration_minute`로 1회
  호출, 블록 높이 갱신, 워크로드 합산 증가.
- **바닥/상한 클램프:** 15분 미만 드래그 → 15분; 종료 시각 초과 → 종료 시각에서 정지.
- **드래그-생성:** 빈 영역 드래그(길이 90분) → `create_task` **정확히 1회**, 빠른추가 컴포저 미발화.
- **합성 클릭 억제:** 드래그 후 `__mockLog`에 create 1회·`onAdd` 0회 확인.
- **겹침:** 같은 시간에 3개 생성 → 3열 균분; 4개째 → "+1 더 보기" 칩 노출, 클릭 시 팝오버에 1개.
- **가상 occurrence:** 루틴 occurrence 리사이즈 → `materialize_if_virtual` 선행 후 갱신, 원본 루틴
  블록은 미변경.
- 검증은 `tauri-v2-browser-audit-mock` 스킬로 시드 데이터를 얹은 실제 컴포넌트를 헤드리스 브라우저에서
  구동(`page.mouse` 드래그 + `__mockLog` 단언).

## 범위 외 (non-goals)

- 주간(Week) 뷰의 리사이즈/드래그-생성 (Phase 2 뷰, 별도).
- 드래그-생성 중의 자연어 제목 파싄(`@시간` 문법) — 생성 후 인라인 입력으로 제목만 입력.
- 겹침 카드 간 시각적 "진행도 연동"(한 카드 완료가 다른 카드에 영향) — 각 카드는 독립.
- 양끝(위쪽) 리사이즈 — 향후 요청 시 추가 가능.
- "+N 더 보기" 칩에서 숨겨진 항목을 보이는 3개로 프로모션/스왑 — v1은 읽기 전용 노출만.
