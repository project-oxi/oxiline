Record 레이어 — 화면 설계

계획된 tape 위를 미끄러지던 재생 헤드가, 이제 실제로 무엇을 했는지 기록한다. 아래는 스펙(docs/superpowers/specs/2026-08-01-record-layer-design.md)에 등장하는 모든 표면을 실제 디자인 토큰(OKLCH, oxi 6색 라벨, Geist/Pretendard)으로 렌더한 mockup이다. 모든 토큰은 crates/oxiline-app/src/styles.css의 활성 정의에서 가져왔다. 충족도(compliance)는 상태 색을 쓰지 않는다 — 초과의 글쓰기(teal)는 빨강이 아니고, 달성한 운동(green)은 트로피가 아니다. 활동 고유 hue와 목표 눈금으로만 표현한다.

설계 노트. §7.1. "합계 기록 4h00m · 미배정 17h (21h 중)" 한 줄이 단일 활동 결정의 보상이다 — 겹치지 않는 세션들이 하루를 분할하므로 $\sum_a \text{spent}_a = \text{총 기록 시간}$ 이 성립하고, "미배정"은 실제로 남은 분배 가능 양이다. 글쓰기 +5m과 운동 달성 라벨은 같은 색으로, 충족도 차이는 오직 채움 길이 + 눈금 + 텍스트로만 표현된다.

표시만 한다. 두 장부를 자동으로 매칭/variance 점수화하지는 않는다 (§3.5, §13). 11:15부터 계획은 "산책"이지만 실제는 "코딩"이 기록됨 — 이 불일치가 보임으로써 계획이 실제와 어디서 어긋나는지 사용자가 자연스럽게 인지한다.

설계 노트. §7.2. 이 한 화면이 새 축의 *정당성*이다 — 계획 tape 위에 기록 tape가 반투명으로 겹쳐 보일 때, plan vs actual이 추상 개념이 아니라 시각적 사실이 된다. 토글 가능 (Preferences).

06

설계 결정 — 돌아와서 확인 요청

세 가지 결정을 대신 내렸다. 번복 가능하니 마음에 안 드는 게 있으면 알려달라.

결정 1
단일 활동(switch)을 v1 핵심으로
스크린타임/전환은 단일 전경 모델. 선택 = 현재 세션 닫고 새로 시작. 시간 분배가 수학적으로 성립한다 — 세션이 분할이므로 $\sum_a \text{spent}_a \le 24h$이고 "남은 시간"이 실제 분배 가능 양이 된다. 동시 추적(overlay)은 wall-clock 이중 집계로 예산 수학이 풀리므로 의식적 분기로 보류 (§13). v2에서 별도 회계 모델과 함께 다룬다.
§3.2 single-active invariant
결정 2
명명: record / activity / session
핵심 은유(playhead / tape)에 맞춰 record를 레이어/동사 이름으로 채택. "consume"은 은유에 안 맞고, "track"은 모호하다. 단위 이름: activity(전환·예산 대상) + session(기록 구간, 1행). 상태: active(기록 중). 예산: target_minutes_daily/weekly. 충족도: compliance.
§2 glossary
결정 3
v1 범위: 타임라인 overlay 포함
전환 패널 + 충족도만으로 끝내면 새 축이 기존 tape에 *보이지 않는* 고아 기능이 된다. Day 타임라인에 반투명 밴드로 기록을 겹치는 것까지 v1에 포함 — 사용자가 plan vs actual을 시각적으로 인지하는 순간이 통합의 핵심이다. 단순 표시(매칭/variance 계산 없음). 빼고 먼저 가고 싶으면 말해달라.
§7.2 timeline overlay
자동 결정의 제약. 비가역 결정을 피하려고 단일 활동/overlay 분기, 활성 세션 invariants, 예산의 중립성 모두를 어디서든 번복 가능한 형태로 디자인했다(데이터는 그대로 두고 start 의미론만 바꾸면 overlay 가능; hue를 바꿔도 데이터 그대로). 그래도 마음에 안 들면 돌아와서 바꿔도 된다.
